# WordPressテーマ化ルール

このファイルは、WordPressテーマの実装前に必ず読む基本ルールです。
詳しい構成例、コード例、例外の判断は `docs/wordpress-reference.md` を確認する。

---

## 1. 作業前の確認

- 対象がトップページ、通常投稿一覧、通常投稿詳細、アーカイブ、固定ページ、固定ページ専用テンプレート、カスタム投稿一覧、カスタム投稿詳細、404ページのどれに該当するか確認する。
- 対象に応じてWordPressのテンプレート階層に沿ったファイルを選び、ページの種類を確認する前にテンプレートを新設しない。
- 対象ページのHTML・PHP・SCSS・JavaScriptと、セクションの入れ子構造を確認する。
- 既存デザイン、既存クラス名、既存の書き方を優先する。
- 実装前に、変更するファイルと変更方針を簡単に説明する。
- 依頼に関係しないリファクタリングや機能追加を行わない。

---

## 2. テンプレートの選択と基本ファイル

- `style.css` の先頭にWordPressテーマヘッダーを書く。
- `screenshot.png` はテーマ直下への配置を推奨する。
- `header.php` に `wp_head()` を入れる。
- `footer.php` に `wp_footer()` を入れる。
- `body` タグに `body_class()` を入れる。
- `index.php` はテンプレート階層の最後の受け皿として用意する。
- トップページは `front-page.php` を使用する。
- 通常投稿の一覧は `home.php`、詳細は `single.php` を基本とする。
- カテゴリー、タグ、日付別などの一覧は `archive.php` を基本とする。
- 通常の固定ページは `page.php`、固有の構成が必要な固定ページは `page-{slug}.php` を使用する。
- カスタム投稿タイプの一覧は `archive-{post_type}.php`、詳細は `single-{post_type}.php` を基本とする。
- 404ページは `404.php` を使用する。
- 実在しないページや投稿タイプ用のテンプレートを先に作らない。

---

## 3. テンプレートパーツ

- `front-page.php` や `page-{slug}.php` は、ページ全体の構成とセクションの表示順を管理する。
- 各セクションのHTML・PHPは、ページごとの `template-parts` 配下へ分割する。
- 各セクションは `get_template_part()` で読み込む。
- ページテンプレートに、複数セクション分の大きなHTMLを直接書かない。
- `front-page.php` や `page-{slug}.php` は、ページ直下に並ぶ親セクションだけを読み込む。
- 親セクションの中に子セクションがある場合は、親パーツから子パーツを `get_template_part()` で読み込む。
- 親パーツは、自身の開始タグ、子パーツの読み込み、自身の終了タグまでを同じファイル内で完結させる。
- 子パーツは自分のHTMLだけを完結させ、親パーツの終了タグを持たない。
- 別のパーツが読み込まれないとHTMLが閉じない構成や、読み込み順に依存してタグが成立する構成を作らない。
- トップページ用のパーツは `template-parts/front/` に配置する。
- 固定ページ用のパーツは `template-parts/{ページスラッグ}/` に配置する。
- 通常投稿用のパーツは `template-parts/post/` に配置する。
- カスタム投稿タイプ用のパーツは `template-parts/{post_type}/` に配置する。
- 複数ページで使う部品は `template-parts/common/` への共通化を検討する。
- `page-{slug}.php` の `{slug}` と、パーツのディレクトリ名はできるだけ揃える。
- 投稿タイプ名と、その投稿タイプ用パーツのディレクトリ名はできるだけ揃える。
- ファイル名は小文字の半角英数字とハイフンを使い、セクションの役割が分かる英単語にする。
- 同じ役割のセクションへ、ページごとに異なる名前を付けない。
- 一覧カード、詳細情報、CTAなど、役割が異なる大きな部品は必要に応じて分割する。
- 短く単純なページやテンプレートは無理に細分化しない。
- 実在するページと投稿タイプに必要なディレクトリだけを作り、空ディレクトリを先に大量作成しない。
- 原則として、1つのテンプレートパーツ内でHTMLタグを完結させる。
- 入れ子のセクションや例外は、`docs/wordpress-reference.md` の判断基準に従う。
- 新しいページを作成する場合も、この構成を基本とする。

## 4. WordPress実装

- CSSは `functions.php` から `wp_enqueue_style()` で読み込む。
- JavaScriptは `functions.php` から `wp_enqueue_script()` で読み込む。
- テーマ内の画像パスには `get_template_directory_uri()` を使用する。
- URL、属性、出力内容に合ったWordPressのエスケープ関数を使用する。
- WordPressのループ、条件分岐、フォーム、URL処理など、PHP化済みの処理を維持する。
- 投稿、固定ページ、カスタム投稿タイプで使用している `the_title()`、`the_content()`、`the_permalink()` などを静的HTMLへ戻さない。
- 管理画面で本文を編集する固定ページでは、既存の `the_content()` を維持する。
- 静的デザインを優先する固定ページでは、既存設計に沿った専用テンプレートを使用する。
- カスタム投稿タイプ固有の処理を通常投稿や固定ページへ混在させない。
- `register_post_type()` の記述が大きくなる場合は、役割別ファイルへの分離を検討する。
- プラグインや別ファイルが投稿タイプを登録している場合は、テーマ側で二重登録しない。
- rewrite、slug、archive、公開状態、REST API対応などの既存設定を維持する。
- `meta description` は、トップページの専用説明文、投稿・固定ページの抜粋など、ページ内容に合う文章を使用する。
- 抜粋が空の場合に備えて共通の説明文を用意し、空の `meta description` を出力しない。
- 共通の説明文は予備として扱い、検索上重要な投稿・固定ページには個別の抜粋または説明文を設定する。
- OGPの `og:url` には、現在表示しているページのURLを設定する。
- 投稿・固定ページではそのページのURL、投稿一覧・カテゴリー・タグ・日付別などの一覧では現在の一覧URLを使用し、一覧ページへトップページURLを固定して出力しない。
- 通常投稿の詳細ページでは `og:type` を `article`、トップページ・固定ページ・一覧ページでは `website` とし、ページの種類に合わせて切り替える。
- まずは必要最小限で動くテーマ化を優先する。

## 5. 別環境での再現

- 固定ページを作る前に、本文を管理画面で編集する設計か、テーマファイルで管理する設計かを確認する。
- 管理画面で本文を編集するページは `page.php` と `the_content()` を使用し、本文がデータベースに保存されることを前提とする。
- 本文とデザインをGitで再現する固定ページは `page-{slug}.php` で管理する。
- `page-{slug}.php` が存在してもURLは自動作成されないため、WordPress管理画面で同じスラッグの固定ページを作成する。
- 新しい環境で必要な固定ページのタイトル、スラッグ、公開状態は、プロジェクト直下の `README.md` に記載する。
- 固定ページへ独自テンプレートが指定されている場合は、`page-{slug}.php` より優先される可能性があるため、管理画面のテンプレート設定を確認する。
- 不要なページテンプレートは、どの固定ページにも割り当てられていないことを確認してから削除する。
- Docker環境を共有する場合は、秘密情報を含まない `.env.example` をGitへ含め、実際の `.env` は `.gitignore` で除外する。
- 環境構築、環境変数、固定ページ作成、起動方法の実作業手順は `README.md` を正本とし、ルール文書へ重複記載しない。
- リポジトリ取得後、`README.md` の手順だけで新しい環境を再現できることを確認する。

## 6. 変更時の禁止事項

- 既存のHTML構造、タグ、class名、id名、文言、表示順を勝手に変更しない。
- CSSやJavaScriptが参照するDOM構造を変更しない。
- 既存のPHP処理を静的HTMLへ戻さない。
- 分割だけが目的の場合は、デザイン、文言、機能を変更しない。
- 分割だけが目的の場合は、URL構造や投稿タイプの登録設定を変更しない。
- 存在しないセクションを追加しない。
- 分割と同時に、不要な共通化やリファクタリングを行わない。
- HTMLの開始タグと終了タグを、理由なく別々のテンプレートパーツへ分けない。
- ページの種類を確認せずにテンプレートファイルを作らない。
- `page.php`、`single.php`、`archive.php` に無関係な処理を集約しない。
- WordPressのテンプレート階層を無視した独自構成にしない。
- 既存の投稿タイプ名やスラッグを推測で変更しない。
- 既存のループ、条件分岐、カスタムフィールド処理を壊さない。

---

## 7. 管理バー

- ログイン中も、サイト表示側のWordPress管理バーは非表示にする。
- WordPress管理画面の管理バーは変更しない。
- 管理バー用のヘッダー位置補正や上部余白が不要になった場合は削除する。

```php
// サイト表示側の管理バーを非表示にする。
add_filter( 'show_admin_bar', '__return_false' );
```

---

## 8. 修正後の確認

- PHP構文エラーがないことを確認する。
- 分割前後で、ブラウザに出力されるHTML、表示順、文言が変わっていないことを確認する。
- 各親パーツ内でタグが完結し、子パーツの読み込み漏れや二重読み込みがないことを確認する。
- ページテンプレートと親パーツの両方から、同じ子パーツを読み込んでいないことを確認する。
- 専用固定ページでは、想定した `page-{slug}.php` が実際に選択され、対象URLが404にならないことを確認する。
- `.env` がGitの管理対象外で、`.env.example` と `README.md` がGitの管理対象になっていることを確認する。
- スマホ・タブレット・PCで表示崩れや横はみ出しがないことを確認する。
- メニュー、FAQ、フォームなど、関連するJavaScriptとPHP処理を確認する。
- 表示確認できなかった場合は、その理由を報告する。
